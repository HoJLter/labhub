# Lab-Hub — сайт-хранилище лабораторных работ

Реализация [TZ-lab-hub.md](TZ-lab-hub.md): публичный каталог методичек/лабораторных с чтением
PDF/DOCX и просмотром видео прямо в браузере, внешние источники файлов (S3, WebDAV, облака,
embed), админ-панель и собственная приватная аналитика.

## Стек и почему он такой

| Компонент | Реализация | Комментарий к ТЗ |
|---|---|---|
| Runtime | **Node.js ≥ 22.13, ESM, ноль npm-зависимостей** | Никаких `node_modules`, рисков цепочек поставок и долгих установок. ТЗ допускал выбор стека (п. 14.1). С 22.13 `node:sqlite` доступен без флага |
| БД | **SQLite (node:sqlite), WAL** | Полноценная SQL-БД: FTS-подобный поиск со стеммингом, JSONB→JSON, агрегаты. Для «сайта для группы» масштаба хватает с огромным запасом; миграция на Postgres не требуется (см. «Путь к Postgres» ниже) |
| Очередь задач | Фоновые таймеры + spawn | Конвертация DOCX, health-check, ретенция — без Redis |
| Веб-сервер | `node:http` + **Caddy** (TLS, gzip/brotli, security-заголовки) | Раздел 9.1 ТЗ |
| PDF-читалка | **PDF.js 4.7 (vendored, офлайн)** | Range-стриминг, миниатюры, оглавление, поиск, зум, темы, hotkeys |
| Деплой | **Dockerfile + docker-compose** (app, caddy, nightly backup) | Раздел 9.1 |
| Заметки | **Vault из .md-файлов** (`data/vault`), формат Obsidian | См. «Заметки» ниже |

## Заметки (в стиле Obsidian)

Отдельный раздел: конспекты и методички с wiki-ссылками, тегами и графом связей.
**Пишутся в Obsidian, читаются всеми**: браузерная часть — только чтение и граф.
Хранилище синхронизируется с Git-репозиторием Obsidian (**односторонний pull**,
настройка в `/admin` → «Синхронизация с Obsidian Git»: URL приватного репозитория,
интервал автосинхронизации, ручная кнопка «Синхронизировать сейчас»).

Главное: заметки — это **настоящие `.md`-файлы** в `data/vault`, а не записи в БД.
Таблицы `notes`/`note_links`/`note_tags` — лишь индекс, он целиком перестраивается из файлов.
Поэтому ту же папку можно открыть в настоящем Obsidian (или любом редакторе) и писать там:
сайт следит за каталогом через `fs.watch` и переиндексирует изменения на лету.
Сам Obsidian внутрь сайта не встроить — это закрытое Electron-приложение без веб-версии,
но совместимость на уровне формата даёт то же удобство.

Что поддерживается:

- **Frontmatter**: `title`, `tags`, `aliases`, `visibility` (`listed`/`unlisted`/`private`);
- **Wiki-ссылки**: `[[Заметка]]`, `[[Заметка|подпись]]`, `[[Заметка#Заголовок]]`, `![[Заметка]]`
  (трансклюзия, до 2 уровней, с защитой от циклов); битые ссылки показываются как «ненайденные»;
- **Вложения**: `![[картинка.png]]` — отдаются из vault с поддержкой Range-запросов;
- **Разметка**: заголовки с якорями, списки, чек-листы, таблицы, сноски, код, callouts
  (`> [!note]`, `[!warning]-` и т. д.), подсветка `==текст==`, теги `#тег` (включая вложенные);
- **Граф**: глобальный (`/notes/graph`) и локальный на странице заметки — силовой layout на canvas,
  pan/zoom/hover, клик открывает заметку; панель настроек как в Obsidian (расстояние между узлами,
  сила отталкивания, притяжение к центру, затухание, размер узлов, размер и прозрачность подписей —
  значения сохраняются в localStorage); узлы-«битые ссылки» помечены пунктиром;
- **Обратные ссылки** и оглавление на каждой странице, страницы тегов `/notes/tags`.

URL: `/notes` — список, `/notes/<slug>` — заметка (slug транслитерируется и **сохраняется при
переименовании файла**, поэтому ссылки не ломаются), `/notes/graph`, `/notes/tag/<тег>`.

Vault по умолчанию лежит в `data/vault` (меняется через `VAULT_DIR`). Каталог `.obsidian` и
скрытые файлы наружу не отдаются. Рендерер markdown собственный (`server/markdown.js`):
HTML из исходника экранируется, опасные схемы URL отбрасываются.

## Быстрый старт

```bash
node server/index.js          # http://localhost:3000  (админка: /admin)
# логин: admin  пароль: admin12345  → смените в Настройки → Учётка
```

Сайт стартует **чистым** — только пустой каталог и админ. Чтобы посмотреть, как всё
выглядит, наполните демо-каталогом (настоящие многостраничные PDF с кириллицей, DOCX,
постеры, видео, статистика за 60 дней):

```bash
node server/seed.js --force   # демо-данные; удаляются пересозданием data/
```

## Деплой на сервер — одной командой

Никаких ручных scp/rsync. С локальной машины:

```powershell
# Windows (PowerShell):
.\deploy.ps1 setup      # один раз: поставит Docker на сервер и настроит SSH-ключ без пароля
.\deploy.ps1            # деплой/обновление: соберёт архив, передаст, поднимет контейнеры
```

```bash
# Linux / macOS / WSL:
./deploy.sh setup
./deploy.sh
```

При первом запуске скрипт спросит IP сервера, SSH-пользователя и домен — и сохранит
в `.deploy.json`. Дальше:

- **`deploy`** — собирает проект в tar (без `data/`, `.git`, `.env`), передаёт по SSH,
  распаковывает, при первом запуске генерирует `.env` со **случайным паролем админа**
  (печатает его один раз!) и поднимает `docker compose up -d --build`;
- **`setup`** — установка Docker + compose-плагина на свежий сервер (Ubuntu/Debian),
  настройка SSH-ключа, открытие портов 80/443;
- **`logs` / `restart` / `down`** — управление сервисом;
- **`backup` / `pull-backup`** — бэкап БД+файлов на сервере и скачивание его к себе.

Обновление сайта после правок = повторный `.\deploy.ps1` (секунды, данные не теряются:
БД и файлы живут в docker-volume `lab-hub-data`).

**HTTPS**: если есть домен — впишите его вместо `:80` в `Caddyfile` (инструкция внутри),
Caddy сам получит сертификат Let's Encrypt. Без домена сайт работает по `http://IP`.

## CI/CD через GitHub Actions

Два workflow в `.github/workflows/`:

- **`ci.yml`** — на каждый push и pull request: проверка синтаксиса всех серверных модулей
  (`node --check`) и полный набор тестов (markdown, vault, graph, e2e) на Node 22.13 и 24.
  Зависимости не устанавливаются — их нет.
- **`deploy.yml`** — на каждый push в `main` (и вручную из вкладки Actions):
  1. тесты;
  2. сборка Docker-образа и публикация в **GHCR** (`ghcr.io/<owner>/lab-hub`) с тегами
     `main` и `sha-<коммит>` (sha-тег позволяет откатиться на любую предыдущую версию);
  3. деплой на VPS по SSH: сервер скачивает образ из GHCR и перезапускает
     `docker compose up -d` (образ, не сборка — деплой быстрый и детерминированный);
  4. проверка `GET /api/site` снаружи — workflow падает, если сайт не поднялся.

### Секреты, которые нужно добавить в репозиторий

Settings → Secrets and variables → Actions:

| Секрет | Обязателен | Значение |
|---|---|---|
| `DEPLOY_HOST` | да | IP или домен сервера |
| `DEPLOY_USER` | да | SSH-пользователь (обычно `root`) |
| `DEPLOY_PASSWORD` | да | SSH-пароль этого пользователя |
| `DEPLOY_PORT` | нет | SSH-порт, по умолчанию 22 |
| `DEPLOY_PATH` | нет | каталог на сервере, по умолчанию `/opt/lab-hub` |
| `DEPLOY_HTTP_PORT` | нет | хостовый порт сайта вместо 80 — если 80 на сервере занят другим сервисом (например, 8080; сайт будет на `http://IP:8080`) |
| `GHCR_USER` + `GHCR_PAT` | нет | только если пакет в GHCR **приватный**: логин GitHub и PAT со scope `read:packages` |

Деплой ходит на сервер по SSH **с паролем** (экшены appleboy/ssh-action и scp-action).
На сервере должен быть разрешён парольный вход: в `/etc/ssh/sshd_config` —
`PasswordAuthentication yes`, затем `systemctl restart ssh`. Если пароль для `root`
не задан — задайте: `passwd root`, либо создайте отдельного пользователя с sudo.

Сайт публикуется **только по HTTP** (порт 80): 443 не занимается, поэтому соседство
с другими сервисами на сервере (например, xray на 443) не мешает. Если занят и порт 80,
деплой остановится с сообщением, какой процесс его держит, — освободите порт или задайте
`DEPLOY_HTTP_PORT` (сайт будет на `http://IP:<порт>`).

Первый деплой сам создаёт на сервере `.env` со случайным паролем админа — он печатается
один раз в логе workflow (job «Деплой на VPS»), сохраните его.

Откат на предыдущую версию: на сервере
`IMAGE=ghcr.io/<owner>/lab-hub:sha-<старый коммит> docker compose up -d`.

## Что реализовано из ТЗ

**Публичная часть (раздел 4):** главная с карточками предметов и «недавно добавленным»;
левый сайдбар — дерево папок одним запросом, состояние в localStorage, фильтр, мобильный
drawer; страница папки — крошки, таблица/карточки, сортировка, фильтры по типу и тегам;
карточка материала — описание, теги, превью, deep-link `?page=N`, «скопировать ссылку»;
поиск с подсказками, подсветкой и логированием «нулевых» запросов; visibility
`listed/unlisted/private`; светлая/тёмная темы; 404; политика конфиденциальности.

**Читалка (раздел 5):** PDF.js + HTTP Range (файл не качается целиком); миниатюры;
оглавление (bookmarks); переход по странице; зум (±, fit-width/fit-page); поворот;
режимы «одна страница / прокрутка / разворот»; ленивый рендер окна ±5 страниц; поиск по
тексту «найден 3 из 17» с подсветкой; текстовый слой (выделение/копирование); темы
день/сепия/ночь (инверсия страниц); печать; запоминание страницы (localStorage) и
восстановление по `?page=`; прогресс-бар чтения; hotkeys (←/→, PageUp/Down, Home/End,
+/−, Ctrl+F, F); мобильный свайп и скрываемый тулбар; страница видео с плеером,
запоминанием позиции и долями досмотра.

**DOCX и видео (раздел 6):** фоновая конвертация DOCX→PDF через LibreOffice headless со
статусами `конвертируется/готово/ошибка` и кнопкой «переконвертировать»; оригинал всегда
доступен для скачивания; постеры и длительность видео через ffmpeg; MP4 с Range-перемоткой.

**Источники (раздел 7):** `local` (Range-стрим), `s3` (собственная реализация AWS SigV4
presigned GET/PUT — AWS, MinIO, Selectel, VK Cloud, B2; режимы redirect/proxy), `webdav`
(proxy с Range, креденшелы из env), `drive` (Google Drive/Яндекс.Диск/Dropbox — embed или
redirect), `url` (proxy с Range), `embed` (YouTube/VK/Rutube iframe). Автоопределение типа
по ссылке. Дисковый LRU-кеш с лимитом `CACHE_MAX_GB`, TTL, janitor'ом и crowd-friendly
фолбэком. Health-check внешних ссылок раз в сутки + вручную, статусы ok/slow/broken, алерты
на дашборде. Загрузка: drag&drop, несколько файлов, прогресс, потоковая запись на диск,
проверка MIME по magic bytes, sha256-дедупликация, лимит размера; presigned PUT для прямой
загрузки в S3.

**Админка (раздел 8):** логин со scrypt-хешем, блокировкой после N неудач, rate-limit и
опциональным TOTP-2FA; CSRF на всех мутациях; дашборд (PV/UV/сессии с динамикой, топ-5,
состояние системы, алерты, audit, «мёртвые» материалы, всплески перед сессией); дерево
папок с drag&drop-перемещением, иконкой/цветом, видимостью, хранилищем по умолчанию;
таблица материалов с фильтрами, массовыми операциями, soft-delete и корзиной (30 дней);
мастер загрузки + attach-external; справочник хранилищ с кнопкой «Тест»; статистика с
графиками, поисковыми запросами, устройствами, источниками и экспортом CSV; настройки
сайта, лимитов, тумблеров (скачивание, поиск, глобальный noindex, закрытый режим);
смена пароля, 2FA, список сессий; экспорт/импорт каталога JSON; журнал действий.

**Аналитика (8.4):** своя, без внешних трекеров. Батчи через `sendBeacon` (~5 с и при уходе),
cookie-идентификатор посетителя (1 год), `HMAC(ip, соль_дня)` с ежедневной ротацией соли,
уважение DNT, фильтр ботов по UA (боты не в главных графиках), сырые `events` + дневные
агрегаты `daily_stats`, ретенция событий 12 месяцев, метрики по каждой лабе: просмотры
карточки, открытия читалки, скачивания, конверсия, средняя дочитанная страница
(`page_change`), доли досмотра видео 25/50/75/100%.

**Нефункциональное (9.4):** security-заголовки (CSP, nosniff, Referrer-Policy, X-Frame-Options,
Permissions-Policy); path-traversal guard; httpOnly SameSite-cookie; mobile-first; контраст AA;
клавиатурная навигация; семантическая вёрстка; SSR-мета (title/description/OG/noindex) для
каждого роута; sitemap.xml и robots.txt, реагирующие на глобальный noindex; ЧПУ `/oop`,
`/m/oop-lab-1`, `/view/oop-lab-1`; структурированные логи и audit; бэкапы.

## Путь к Postgres (если проект вырастет)

Слой данных изолирован в `server/db.js` (prepare/run/get/all — те же семантики, что и у
pg-драйвера). При переходе: заменить DatabaseSync на pg-Pool, `AUTOINCREMENT`→`SERIAL`,
JSON-колонки→`JSONB`, LIKE-поиск→`tsvector` с русской морфологией (`pg_ru_dict`/парсер),
`events`→партиционированная таблица. Остальной код не меняется.

## Эксплуатация

- **Переменные окружения:** см. `.env.example`.
- **Секреты хранилищ:** в админке укажите `env:S3_SECRET` — значение подставится из
  окружения, в БД секрет не попадёт (раздел 7.1).
- **Бэкап/восстановление:** `node scripts/backup.js`; восстановление — остановить сервис,
  вернуть `db-*.sqlite` как `data/lab-hub.sqlite` и распаковать `files-*.tar` в `data/`.
- **Мониторинг:** `GET /api/site` — health-check эндпоинт (используется HEALTHCHECK Docker).
- **Рекомендация из раздела 13 ТЗ выполнена:** каталог по умолчанию `noindex=true` —
  материалы вуза не индексируются поисковиками, пока вы явно не отключите тумблер в настройках.
