## 1. Цель проекта

Сделать собственный сайт, на котором публикуются лабораторные, практические и методички,
выданные в вузе. Сайт решает три задачи:

1. **Чтение.** Пользователь находит нужный предмет (ООП, ВЕБ и т.д.) в левом меню, открывает
   материал и читает его прямо в браузере, не скачивая (PDF, DOCX), либо смотрит видео (MP4).
2. **Хранение без привязки к железу.** Материалы лежат не только на диске сервера, но и во
   внешних источниках (S3-совместимое хранилище, WebDAV, облако, просто ссылка) — сервер
   остаётся «тонким», а каталог единым (раздел 7, ключевая часть проекта).
3. **Администрирование.** Админ через веб-панель создаёт папки-предметы, публикует материалы,
   видит статистику посещаемости и активности по каждой лабораторной.

Что НЕ входит в проект: система сдачи работ с дедлайнами, личные кабинеты студентов,
онлайн-редактирование документов, форум/чат, оценки, интеграция с LMS вуза.

## 2. Термины

| Термин | Значение |
|---|---|
| Материал | Одна единица контента: PDF, DOCX, MP4, изображение или внешняя ссылка |
| Папка | Предмет/раздел каталога, поддерживает вложенность (ООП → Лабы → Лаба 3) |
| Источник | Место физического хранения файла: сервер, S3, WebDAV, облако, внешний URL |
| Читалка | Встроенный просмотрщик (PDF-вьюер, конвертер DOCX, видеоплеер) |
| Админ | Единственная привилегированная роль, владелец сайта |
| Гость | Любой посетитель без входа, права только на чтение |

## 3. Роли и модель доступа

Принято (из ответов):

* Сайт **публичный**, без входа для читателей. Кнопок «регистрация»/«войти» в публичной части нет.
* Загружать материалы может **только админ**. Остальные — читатели.
* Единственная защищённая зона — `/admin`.

Следствия и требования:

* Учётных записей студентов в БД нет. Персональные данные не собираются (кроме обезличенной статистики, раздел 8).
* Поскольку сайт публичный, **каждый материал имеет флаг `noindex`/`unlisted`**:
  * `listed` — попадает в каталог, поиск и sitemap;
  * `unlisted` — доступен по прямой ссылке (кинуть в чат группе), но не индексируется и не виден в каталоге;
  * `private` — доступен только админу (черновик/служебное).
* Опционально (Phase 2, заложить в схему БД сразу): «закрытый режим» — сайт доступен только
  по инвайт-коду или общему паролю группы. Реализуется одним middleware, чтобы включить без переделки.
* Авторизация админа: единственный аккаунт (email/логин + пароль), хеш Argon2id,
  сессия в httpOnly-cookie, 2FA (TOTP) как опция, rate-limit на форму входа, блокировка после N неудач.

## 4. Публичная часть (то, что видят пользователи)

### 4.1 Главная страница
* Список папок-предметов карточками: название, краткое описание, число материалов, иконка/цвет.
* Блок «Недавно добавленное» (последние N опубликованных материалов).
* Строка поиска по названиям, описаниям и тегам.
* Переключатель темы (светлая/тёмная).

### 4.2 Левый сайдбар — навигация по каталогу
* Иерархическое дерево папок с раскрытием/сворачиванием, состояние сохраняется в localStorage.
* Счётчик материалов рядом с папкой.
* Строка фильтра по дереву (мгновенный поиск папки).
* На мобильных сайдбар становится выдвижной панелью (drawer) с кнопкой-гамбургером.
* Дерево загружается одним запросом (кешируется), а не по узлу.

### 4.3 Страница папки
* Хлебные крошки, описание папки.
* Список материалов: таблица или карточки (переключатель), сортировка по дате/названию/типу,
  фильтр по типу файла (PDF / DOCX / MP4 / другое) и тегам.
* Колонки: иконка типа, название, размер, дата, просмотры, кнопки «Читать»/«Скачать».

### 4.4 Карточка материала
* Название, описание (markdown-lite), теги, автор/предмет, дата загрузки, размер, страницы/длительность.
* Превью первой страницы PDF / постера видео / первой страницы DOCX.
* Кнопки: «Читать онлайн» (основная), «Скачать» (если разрешено), «Скопировать ссылку на страницу».
* Deep-link: `?page=12` открывает читалку на нужной странице; хеш `<a id="material-...">`.
* Опционально: комментарии/заметки — НЕ входит в MVP, вынесено в «не входит».

### 4.5 Поиск
* Полнотекстовый поиск по названию + описанию + тегам (Postgres FTS с русской морфологией).
* Подсказки по мере ввода, подсветка совпадений.
* Опционально (Phase 2): поиск по тексту внутри PDF — требует извлечения text layer при публикации.
* Журналировать поисковые запросы и «нулевые» результаты (что искали и не нашли) — это прямо в админскую статистику (раздел 8).

### 4.6 Хлебные крошки, навигация
«Главная / ООП / Лабораторные / Лаба 3» — кликабельные уровни; кнопка «назад к списку» из читалки.

## 5. Читалка PDF — детальные требования

Основа: PDF.js (рендер в canvas + текстовый слой). Читалка — отдельный route `/view/:id`.

Обязательно:
* Прогрессивная загрузка и **HTTP Range-запросы**: открытие файла на 300 МБ не должно тянуть весь файл.
* Навигация: панель миниатюр страниц, оглавление (если PDF содержит bookmarks), переход по номеру страницы.
* Запоминание последней прочитанной страницы на материал (localStorage; опционально — в БД по анонимному id).
* Индикатор прогресса чтения (полоса снизу + процент).
* Зум (+, −, fit-width, fit-page, 100%), поворот страницы.
* Режимы отображения: одна страница / непрерывная прокрутка / разворот (двухстраничный).
* Поиск по тексту с подсветкой всех совпадений и переходом «найден 3 из 17».
* Выделение и копирование текста (текстовый слой поверх canvas).
* Тёмная тема чтения: инверсия страницы (не только интерфейса), режимы «день/сепия/ночь».
* Скачивание и печать (кнопки, если материал не помечен как «только чтение»).
* Горячие клавиши: стрелки/PageUp/PageDown, +/−, Ctrl+F, Home/End, F — полный экран.
* Мобильные: pinch-zoom, свайп между страницами, скрываемый тулбар, работа на iOS Safari.
* Восстановление после потери связи и запоминание позиции при перезагрузке.
* Ленивая подгрузка страниц (окно ±5) ради памяти на слабых ноутбуках.

Пояснение по принятому дефолту: аннотации/заметки (выделения, стикеры, freehand) в MVP
**не входят** — они требуют хранения состояния. Заложены в Phase 2 как локальные аннотации
в IndexedDB (без входа на сайт) с экспортом/импортом, чтобы не смешивать данные разных людей.

## 6. Просмотр DOCX и видео

### 6.1 DOCX
Выбран вариант **предпросмотр в браузере + скачивание**.
* При публикации DOCX сервер фоновой задачей конвертирует его в PDF через LibreOffice headless
  в отдельном контейнере. Результат кешируется рядом с материалом (`converted/`).
* Просмотр идёт в той же PDF-читалке (единый UX, ноль дополнительного кода).
* Fallback: если конвертация упала — отдать HTML-рендер (mammoth) без вёрстки либо предложить скачать.
* В админке у материала виден статус: `конвертируется / готово / ошибка конвертации` + кнопка «переконвертировать».
* Оригинальный `.docx` всегда доступен для скачивания.
* Поддерживать также `.doc`, `.pptx`, `.xlsx` той же схемой — «бесплатно» получается из LibreOffice (Phase 2).

### 6.2 Видео (MP4)
* HTML5-плеер (Plyr или Video.js): play/pause, перемотка, громкость, скорость 0.5–2×, полный экран,
  Picture-in-Picture, горячие клавиши, запоминание позиции просмотра.
* Обязательная поддержка **Range-запросов** (иначе перемотка в MP4 не работает).
* Постер-кадр генерируется на сервере (`ffmpeg`) при публикации; опционально превью-скраббинг.
* Субтитры VTT, если загружены (опционально).
* Опционально (Phase 3): transcoding в HLS (720p/1080p) для экономии трафика и адаптивного качества —
  только если по статистике видно проблемы. В MVP — progressive MP4.
* Для больших файлов рекомендован режим «внешний источник + embed/proxy» (раздел 7).

## 7. Источники контента и работа с большими файлами (ключевой раздел)

Проблема: сервер есть, но материалы (особенно видео) могут весить много; ставить всё локально —
значит упереться в диск и канал. Решение: **каталог отдельно от файла**. В БД хранятся метаданные,
а физический файл находится там, где удобно; тип источника — свойство материала.

### 7.1 Типы источников (`source_type`)

| Тип | Что это | Как отдаётся читателю |
|---|---|---|
| `local` | Файл на диске сервера | Поток напрямую с Range |
| `s3` | S3-совместимое хранилище (AWS S3, MinIO, Selectel, VK Cloud, Backblaze B2) | Presigned URL + redirect, либо proxy через сервер |
| `webdav` | WebDAV-хранилище (в т.ч. Яндекс.Диск WebDAV, Nextcloud) | Proxy-stream с Range, дисковый кеш |
| `drive` | Публичная ссылка Google Drive / Яндекс.Диска / Dropbox | Embed-iframe или proxy через публичный API |
| `url` | Прямая ссылка на файл где угодно | Proxy-stream с Range, дисковый кеш |
| `embed` | Внешний плеер/вьюер (YouTube, VK Видео, Rutube, Kodik) | iframe страницы материала |

Для каждого материала хранится `source_config` (JSONB): bucket/key или folder id, публичная ссылка,
ссылка на учётные данные (не сами секреты — они в env/секрет-хранилище), режим отдачи.

### 7.2 Три режима отдачи и когда какой применять
1. **redirect** — сервер выдаёт временную подписанную ссылку, браузер качает напрямую.
   Плюс: не тратит трафик и диск сервера. Минус: нет точного учёта скачиваний, зависит от CORS и от лимитов источника.
2. **proxy** — сервер сам тянет поток от источника и отдаёт клиенту, поддерживая Range (склейка чанков).
   Плюс: точная статистика, единая авторизация, работает с любым источником. Минус: трафик и CPU сервера.
3. **embed** — вообще не файл, а плеер источника в iframe.
   Плюс: ноль затрат. Минус: чужой UI, реклама/баннеры, статистика просмотров только внешняя.

Правило по умолчанию: PDF и DOCX (мелкие) → `proxy` или `local`; крупное MP4 на S3 → `redirect`;
крупное MP4 на облаке без API → `embed`; редкие архивные материалы → `redirect`.

### 7.3 Дисковый кеш на сервере (обязательный компонент)
* Кеш-каталог с лимитом (`CACHE_MAX_GB`, например 20 ГБ), вытеснение по **LRU**.
* В кеш попадают: PDF-оригиналы и их конвертации, постеры, миниатюры, часто читаемые внешние файлы.
* Видео по умолчанию **не кешируется** (только стриминг), либо кешируется лишь при явном флаге.
* TTL для файлов из внешних источников, фоновая проверка актуальности.
* Health-check внешних ссылок раз в сутки (HEAD-запрос): статус `ok / slow / broken`,
  в админке значок «ссылка сломана» + список проблемных материалов на дашборде.
* Crowd-friendly: если внешний источник отвалился, а файл есть в кеше — отдавать из кеша.

### 7.4 Загрузка файлов
* Браузерная загрузка drag&drop, несколько файлов сразу, прогресс по каждому.
* Для `local`: лимит на файл (по умолчанию 2 ГБ), потоковая запись на диск без загрузки в память.
  Опционально chunked-upload (tus) с докачкой при обрыве — Phase 2.
* Для `s3`: **прямая загрузка браузер → S3** через presigned multipart URL, минуя сервер (важно для больших видео).
* Проверка MIME по magic bytes, а не по расширению; пересчёт checksum (sha256); опционально ClamAV.
* Дедупликация по checksum: повторная заливка того же файла не тратит место.
* Показывать админу свободное место и предупреждать при заполнении >85%.

### 7.5 Управление источниками в админке
* Справочник «Хранилища»: добавить/редактировать источник, проверить соединение кнопкой «Тест».
* При создании материала два пути: «Загрузить файл» или «Указать внешний источник»
  (вставить ссылку → система сама определит тип, проверит доступность, вытянет размер и MIME).
* Для папки можно задать хранилище по умолчанию, чтобы не выбирать каждый раз.

## 8. Админ-панель

Зона `/admin`, отдельная вёрстка (плотная, табличная), защищённая авторизацией.

### 8.1 Дашборд
* Визиты за 24ч / 7д / 30д, тренд, сравнение с предыдущим периодом.
* Топ-5 материалов и папок по просмотрам.
* Состояние системы: занятое место, размер кеша, свободно на диске, статус внешних хранилищ.
* Последние действия (audit log), последние публикации.
* Алерты: сломанные ссылки, ошибки конвертации, диск > 85%.

### 8.2 Управление каталогом
* Дерево папок: создание, переименование, перемещение (drag&drop), удаление (с проверкой,
  что внутри), порядок вручную, иконка/цвет, описание (markdown).
* Черновики папок (не видны публично до публикации), флаг `listed/unlisted/private`.
* Массовые операции: переместить N материалов, изменить теги, распубликовать.

### 8.3 Управление материалами
* Таблица с фильтрами (папка, тип, источник, статус, дата), поиском, сортировкой.
* Публикация, редактирование метаданных, замена файла, перемещение, удаление (soft delete + корзина на 30 дней).
* Пакетная загрузка: выбор папки → перетаскивание файлов → автоматическое определение названия из имени файла.
* Автогенерация превью, страниц, длительности; статус обработки.
* Теги: справочник + автодополнение; назначение тегов массово.

### 8.4 Статистика (детально)
Сбор собственный, без Google Analytics.

Метрики обязательные:
* **Посещения**: просмотры страниц (PV), уникальные посетители (UV), сессии, отказы, среднее время на сайте.
* **Разрезы**: по дням/неделям/месяцам, фильтр по дате, выбор папки/материала.
* **По каждой лабораторной**: просмотры карточки, открытия читалки, скачивания, среднее время чтения,
  до какой страницы обычно дочитывают (событие `page_change`), для видео — доля досмотра 25/50/75/100%,
  конверсия «открыл карточку → начал читать», количество «вернулись и продолжили».
* **Топы**: популярные материалы, папки, скачивания.
* **Поиск внутри сайта**: что искали, популярные запросы, запросы без результатов.
* **Технические**: источники переходов, устройства (desktop/mobile/tablet), браузеры, ОС, разрешение экрана.

Метрики предлагаемые (сверх вашего запроса, включаются галочками):
* География по стране/городу (локальная база GeoLite2, без внешних сервисов).
* Тепловая карта активности по часам и дням недели.
* «Мёртвые» материалы: 0 просмотров за 90 дней.
* Статистика по источникам хранения: сколько трафика отдал сервер, сколько внешние хранилища.
* Воронка «за неделю до сессии» — резкий рост просмотров по предмету.

Требования к реализации:
* Анонимность: не хранить IP в открытом виде — хранить `HMAC(ip, salt)` с ротацией соли раз в сутки,
  cookie-идентификатор сессии (first-party, 1 год), уважать DNT.
* Фильтрация ботов по User-Agent + список известных диапазонов; отдельная метрика «боты» не считается в главных графиках.
* Собственная таблица событий (`events`) с партиционированием по месяцам; агрегаты по дням в отдельной таблице,
  чтобы графики не считались по сырым событиям.
* Батчевая отправка событий с фронта (маячок `sendBeacon`, раз в ~5 сек или при уходе со страницы) —
  чтобы не тормозить чтение PDF.
* Экспорт отчётов в CSV, фильтры сохраняются в URL.
* Ретенция: сырые события 12 месяцев, агрегаты — бессрочно.
* Рекомендация: не изобретать всё с нуля — поставить self-hosted **Umami** для базовой веб-аналитики
  (посещения, источники, устройства, гео) и дописать собственные события для метрик «по лабам».
  Это сокращает объём работы примерно вдвое и остаётся без внешних зависимостей.

### 8.5 Настройки
* Название сайта, логотип, описание, favicon, контакт/подпись в подвале.
* Тема по умолчанию, акцентный цвет.
* Лимиты: максимальный размер загрузки, размер кеша, разрешённые типы файлов.
* Тумблеры: разрешено ли скачивание, включён ли публичный поиск, режим `noindex` для всего сайта.
* Управление источниками хранения (раздел 7.5), тестами соединения.
* Управление учёткой: смена пароля, включение 2FA, список активных сессий.
* Экспорт/импорт конфигурации каталога (JSON) — вместе с бэкапами.

## 9. Технические требования

### 9.1 Рекомендуемый стек (требует подтверждения, п. 14.1)
* **Frontend + Backend**: Next.js (App Router) на Node.js — SSR важен для публичного сайта (SEO, быстрый первый экран) и для отдачи Range-стримов.
* **БД**: PostgreSQL 16 (FTS, JSONB, партиционирование).
* **Очередь фоновых задач**: BullMQ + Redis (конвертация DOCX, генерация постеров, health-check ссылок).
* **Файлы**: локальный диск + S3-совместимый клиент; LibreOffice headless и ffmpeg — в отдельных контейнерах.
* **Веб-сервер/прокси**: Nginx или Caddy (TLS, gzip/brotli, отдача статики, отдача Range для локальных файлов).
* **Развёртывание**: docker-compose на вашем сервере (app, postgres, redis, worker, libreoffice, caddy).
  Плюс nightly `pg_dump` и rsync/бэкап каталога материалов.
* Альтернативы, если удобнее: Python (FastAPI + SQLAlchemy + Celery) — функционально эквивалентно;
  PHP (Laravel) — возможно, но стриминг и читалка потребуют больше ручной работы.

### 9.2 Схема БД (укрупнённо)
* `folders` — id, parent_id, slug, title, description, icon, color, position, visibility, created_at, updated_at
* `materials` — id, folder_id, slug, title, description, kind (pdf/docx/video/image/link), mime, size,
  source_type, source_config (jsonb), storage_id, checksum, page_count, duration_sec, poster_path,
  converted_path, status (processing/published/hidden/deleted), visibility, allow_download,
  views_count, downloads_count, published_at, created_at, updated_at
* `tags`, `material_tags`
* `storages` — id, name, type, config (jsonb), is_default, health_status, last_check_at
* `link_health` — material_id, status, http_code, checked_at, error_msg
* `cache_entries` — material_id, path, size, last_access_at, expires_at
* `sessions`, `visitors` (анонимный id), `events` (партиционированная), `daily_stats` (агрегаты)
* `search_queries` — query, results_count, created_at
* `settings` (key/value), `audit_log` — actor, action, entity, payload, created_at
* `admin_users` — id, login, password_hash, totp_secret, last_login_at

Индексы: `materials(folder_id, status)`, `materials(published_at desc)`, GIN по FTS-вектору,
`events(material_id, created_at)`, `events(created_at)`.

### 9.3 API (ориентировочно)
Публичные: `GET /api/folders/tree`, `GET /api/folders/:slug`, `GET /api/materials/:slug`,
`GET /api/search?q=`, `GET /api/stream/:id` (Range), `GET /api/download/:id`, `POST /api/events` (батч метрик).
Админские (`/api/admin/*`, под авторизацией): CRUD папок и материалов, `POST /upload`,
`POST /materials/:id/attach-external`, `POST /storage/test`, `GET /stats/*`, `GET /export/*`.
Все мутирующие запросы — с CSRF-токеном; ограничение частоты на `POST /api/events` и на логин.

### 9.4 Нефункциональные требования
* Производительность: TTFB < 300 мс на кешированной странице, первый экран читалки < 1.5 с,
  открытие 500-страничного PDF без скачивания файла целиком.
* Мобильный-first: полноценная работа на телефоне, включая чтение PDF и просмотр видео.
* Поддержка браузеров: последние 2 версии Chrome, Edge, Firefox, Safari (в т.ч. iOS).
* Дизайн: современный и не перегруженный — чистые поверхности, аккуратная типографика, Inter/system-ui,
  мягкие тени, скругления, один акцентный цвет, тёмная и светлая темы, никаких лишних анимаций.
  Каркас публичной части: **левый сайдбар с деревом папок** + контентная область; читалка — на всю ширину
  с тонким тулбаром и выдвижным оглавлением. Админка — та же палитра, но плотнее и табличнее.
* Доступность: контраст WCAG AA, полная работа с клавиатуры, alt-тексты, семантическая вёрстка.
* Язык интерфейса: русский (структура готова к добавлению английского, строки вынесены в словарь).
* Безопасность: HTTPS обязателен, security-заголовки (CSP, X-Content-Type-Options, Referrer-Policy),
  санитайзинг описаний, отсутствие path traversal при отдаче файлов, подписанные ссылки на внешние ресурсы,
  бэкапы БД ежедневно, мониторинг доступности и свободного места с уведомлением.
* SEO: SSR, sitemap.xml, ЧПУ `/oop/laba-3`, Open Graph-картинки для материалов, meta-описания,
  флаг `noindex` на материал и глобальный тумблер.
* Логирование: структурированные логи, отдельный audit log административных действий.
* Приватность: без сторонних трекеров, политика конфиденциальности одной страницей.

## 11. Этапы работ

**Phase 1 — MVP (ядро).**
Каталог папок, загрузка PDF/DOCX/MP4 на `local`, автопревью/постеры, PDF-читалка с Range,
DOCX-конвертация, видеоплеер, публичная навигация с левым меню, админка (папки, материалы, настройки),
базовая статистика (посещения + по материалам), Nginx/TLS, бэкапы.

**Phase 2 — источники и удобство.**
Внешние хранилища (S3, WebDAV, drive, url, embed), дисковый кеш с LRU, health-check ссылок,
прямая загрузка в S3, chunked-upload, теги и расширенный поиск, экспорт статистики,
локальные аннотации в PDF, «закрытый режим» по инвайт-коду.

**Phase 3 — по потребности.**
Поиск по тексту внутри PDF, transcoding в HLS, поддержка pptx/xlsx/doc, комментарии,
шеринг ссылок с ограничением по времени, PWA/офлайн-кеш читалки, мультипользовательские роли.

## 12. Критерии приёмки

* Админ может создать папку «ООП» и подпапку «Лабораторные», загрузить в неё PDF, DOCX и MP4,
  и все три открываются и читаются в браузере без скачивания.
* PDF на 200+ МБ открывается, листается, перематывается и ищется по тексту, не загружаясь целиком.
* Видео перематывается (проверяется реальный Range 206), сохраняет позицию при возврате.
* Материал, взятый из внешнего источника, отображается и открывается так же, как локальный;
  при недоступности источника админ видит алерт.
* Дисковый кеш не превышает заданный лимит и вытесняет старые записи по LRU.
* В админке есть графики посещений по дням и таблица просмотров/скачиваний по каждой лабораторной с экспортом CSV.
* Публичный посетитель не может загружать, удалять или изменять контент ни одним способом.
* Сайт корректно работает на телефоне (чтение PDF и видео), Lighthouse performance ≥ 85 на десктопе.
* Восстановление из бэкапа проверено: БД поднимается, файлы на месте.

## 13. Риски и замечания

* **Публичность + материалы вуза.** Методички и задания могут быть объектом авторских прав, а публичный
  открытый каталог легко находится поисковиками. Рекомендация: держать каталог `noindex` по умолчанию,
  либо включить «закрытый режим» (инвайт-код), либо использовать `unlisted` для чувствительных файлов.
* **Трафик.** 30 человек × просмотр 300-МБ видео = ~9 ГБ на одну лабу. Поэтому внешние источники и
  режим `redirect`/`embed` — не «фича на будущее», а способ не убить сервер и канал.
* **Конвертация DOCX/видео** — самая хрупкая часть: нужны контейнеры LibreOffice/ffmpeg, контроль
  очереди и лимиты CPU, иначе фоновые задачи подвесят сайт.
* **Внешние ссылки живут своей жизнью**: файл по ссылке может быть удалён владельцем. Нужен health-check
  и, для критичных материалов, локальная копия в кеше.
* **Своя аналитика** требует дисциплины по приватности (см. 8.4) и партиционирования, иначе таблица событий распухнет.

## 14. Открытые вопросы (нужно подтвердить перед стартом)

1. **Стек.** Согласны на Next.js + Postgres + Redis + Docker на вашем сервере, или есть предпочтения/ограничения сервера (ОС, RAM, диск, уже занятые порты, root-доступ, Docker)?
2. **Читалка PDF.** Вы не выбрали пункты — я взял дефолт: миниатюры, поиск по тексту, зум, режимы страниц,
   тёмная тема, запоминание страницы, hotkeys, мобильный. Какие из этого лишние, и нужны ли аннотации/заметки?
3. **Структура каталога.** Дефолт: вложенные папки-предметы + теги (семестр, преподаватель, тип работы) + черновики.
   Нужны ли теги, или достаточно одних папок?
4. **Какие внешние источники у вас реально есть?** Ключи S3/WebDAV, платный ли Яндекс.Диск, аккаунт Google Drive.
   От этого зависит, какие адаптеры делать первыми.
5. **Учётная запись админа.** Один аккаунт с паролем или нужен 2FA (TOTP-приложение)?
6. **Домен и HTTPS.** Есть ли домен и открыт ли 80/443 на сервере, нужен ли доступ по IP.
7. **Лимиты.** Максимальный размер одного файла при загрузке на сервер, желаемый размер дискового кеша, сколько всего материалов ожидается (десятки/сотни/тысячи) и примерный объём.
8. **Обязательные ли видео-файлы локально.** Нужна ли вообще загрузка MP4 на сервер, или видео только
   через внешние источники/embed (YouTube, VK, Rutube)?
9. **Поиск по содержимому PDF** нужен сразу или достаточно поиска по названию/тегам?
10. **Сроки и объём.** Это проект «для себя и группы» в свободном темпе, или нужны фиксированные этапы
    с датами? Нужна ли помощь с дизайн-макетами или вёрстка «на глаз» по разделу 10?
